## Deviations from the guide / prompt

1. **Stage 1 had no LLM nodes.** The guide's Portfolio Agent and Sentiment Agent were already code before M1 (consistent with D2 and D3). No LLM call was removed.
2. **Prompt-level leak found in M0.** The shortlist reason (`underperformer` vs `at_risk`) is decided by the sign of the unrealized gain, which is cost-basis-derived. Prompts therefore get `risk` (underperformer and at_risk) or `opportunity`; the UI/API keeps the exact label.
3. **TKG run identity.** `tkg.sector_impacts` returns no run id; the sector-narrative cache key uses the snapshot's `as_of` timestamp as `tkg_run_id`. A new snapshot is a cache miss; with no `as_of` nothing is cached.
4. **Cache sharing needs a portfolio-independent prompt.** The Sector agent's input is sector-level only. Its `affected_holdings` is chosen among the sector's securities that have TKG company evidence (`TkgProvider.sector_candidates`, portfolio independent), validated against that candidate list at generation, and intersected with the securities the portfolio actually holds in that sector at run time. The prompt's "held securities" wording is thus applied at read time, not generation time.
5. **Cache write policy.** Only validated LLM output is cached; template fallbacks are not (an outage must not freeze a template for the whole snapshot). A cache or database failure never fails a run (`PgAppStore` degrades to a miss and counts errors).
6. **Sentiment output and one fusion rule (owner, 7 Nov).** `neutral` is |weighted score| < 0.10 (the band the other Stage 1 nodes use); `insufficient` is fewer than `SENTIMENT_MIN_ARTICLES` scored articles or total weight 0. `publisher` is the article's `source_id`. For ALL Stage 1 components (structural, sentiment, sector) a neutral signal (|signal| < 0.10) and an unavailable one (insufficient news, no sector signal) are recorded and shown in `stage1_*` but excluded from the fused average, so a non-signal never dilutes a real one. A signal of exactly 0.10 counts. Consequence: a concentrated portfolio's structural penalty alone (e.g. -0.37) can now flag a holding when its other components are neutral; the fixtures were adjusted accordingly.
7. **Fundamentals metrics.** Percent metrics are stored in percent, so the numbers the LLM narrates are the numbers shown to it. Free cash flow is exposed as `fcf_margin_pct` (TTM FCF over TTM revenue), not an absolute amount, so no monetary figure is in a prompt. Quarters are matched by date: a skipped reported quarter (the recorded TCS fixture lacks 2025-09-30) makes the year-over-year metrics `missing`, never a wrong figure. Interest coverage is `missing` when there is no interest expense (undefined, not infinite). `stale` = latest quarter older than `FUNDAMENTALS_STALE_DAYS` (200).
8. **Number faithfulness (owner, 7 Nov: signs matter).** A number in an LLM rationale must equal a shown, signed value as rounded. An explicit sign must equal the value's sign. An unsigned number matches a positive value, and matches a negative value only when the words around it (6 before, 2 after) state a falling direction (fell, declined, down, lower, ...) and no rising one; a flipped direction ("rose 3.2" for -3.2) and a bare "3.2" for -3.2 both fail. Window labels ("6-month", "4 quarters") and the parts of the shown results date stay exempt. The prompts tell the models this rule. Code: `core/faithfulness.py`.
9. **Vote aggregation.** Stances map to -1/0/+1; weights are settings (default 1/3 each) re-normalised over voters that are not `no_data`; conflict = at least two voters with confidence >= 0.5 holding supportive and concerning. `status`, `attention` and `direction_label` shown by the API are derived from the vote (`attention` high when |consensus| >= 0.5 or a conflict). The old fixed 0.4/0.6 weights and `scoring.vote` are removed.
10. **Conflict Resolver edge.** The graph has a conditional edge after `stage2`: `conflict_resolver` only when at least one stock's votes conflict, else straight to `synthesis`. The resolver runs per conflicting stock, on the `synth` model role (`AGENTS_SYNTH_LLM_MODEL`). Its template fallback picks the type from which voters disagree (`news_vs_fundamentals`, `technical_vs_fundamental`, else `other`).
11. **Sector agent model role.** It uses the cheaper `stock` role (`AGENTS_LLM_MODEL`); the Fundamental agent too.
12. **Migrations (owner, 7 Nov: Alembic).** `services/agents/alembic/` (version table `app.alembic_version`, same pattern as the TKG), run by `python -m finsight.migrate upgrade|downgrade|current|stamp --target test|main` as the `finsight_app` login; any change to MAIN refuses without `--confirm-main`. `0001_cache_tables` is idempotent (`IF NOT EXISTS`), because TEST already held the tables from the earlier SQL-file runner (removed); TEST is now at revision 0001 and an up/down/up test runs on TEST. MAIN is not migrated (waits for M4/M5 and the owner's confirmation); until then MAIN runs use an uncached path (reads fail soft).

## M3 (synthesis, compliance, privacy, evidence hygiene)

13. **Synthesis is grounded.** Code assembles an evidence list (`flow/synthesis.py::build_evidence`: portfolio structure, flag drivers, structural / sentiment / sector-signal reads, article headlines, sector narratives, the three verdicts, the vote, the resolver's explanation), each item with an id. The model cites ids; ids it invents are dropped; a stock may cite only its own evidence; a stock summary with no valid citation is replaced by the code template for that stock; a shortlisted stock the model omits gets its code summary. `data_notes` is written by code, never by the model.
14. **Provider wording is code.** `provider_note` is built from the recorded `sector_signal_source` (fixes the "(tkg_lite)" bug at its root: the old prompt told the model to write it). The model is told not to name data sources; `tkg`, `tkg_lite`, `knowledge graph` in its text is a compliance violation. The API returns the note in `meta.sector_provider_note` and appended to `sector_notes`.
15. **Framing is code.** Risk-flagged holdings are introduced as "Flagged for a closer look (risk signals)", opportunities as "Worth a closer look (positive signals)". Prompts only ever see `risk` / `opportunity`.
16. **Compliance.** Banned: buy, sell, hold, trim, hedge, exit, accumulate, must (whole words); book profit, target price, stop loss, recommend, you should, should invest, we suggest, invest in, add to your position, reduce your position. Beyond the list, the pass also rejects provider wording and any number in the model's text that is not in the evidence (sign-aware). One regeneration, then the template. The outcome (`passed` | `regenerated` | `template`, the violations, the checks) is stored per run in `compliance_outcome` and returned in the API; the disclaimer is always appended in code.
17. **Evidence hygiene.** A headline ending in "?" or containing "to buy", "should you", "target price" or "stop loss" is left out of every evidence the user or the model sees: sentiment top headlines, cited recheck articles, TKG path items and company evidence. The scores are not recomputed (the TKG score and the sentiment score still use every article); counts are in `evidence_exclusions` (`sentiment_headlines`, `recheck_articles`, `tkg_evidence_items`) and `meta.evidence_excluded`.
18. **Privacy filter.** `core/privacy.py` is applied by `LLMClient` to every outgoing prompt: forbidden JSON keys (quantity, average_cost, current_price, anything unrealized / pnl, user_id, bare weight, email, ...), email addresses, and the run's own long values (user id, quantities and costs of 5+ characters) raise `PrivacyError` before any call. Short values cannot be registered safely (a quantity of 10 vs "10 articles"), so the builders use allow-lists and `tests/test_m3.py` captures every prompt of a full run (recheck, fundamental, sector, resolver, synthesis, regeneration) on a portfolio with distinctive private values.
19. **`live_smoke` marker.** `tests/test_live_smoke.py` makes exactly one real call (no retry, no repair: `LLMClient.complete_raw`) each to the Sector agent, the Fundamental agent and the Conflict Resolver from recorded inputs (`tests/fixtures/live_smoke/`) and prints the raw outputs and the validator's verdict. It is skipped unless `--run-live-smoke`; not run yet (the TKG backlog uses the Gemini quota).

## M4 (API, portfolios, async runs, tracing)

20. **Portfolios** live in `app.portfolios` / `app.holdings` (Alembic `0002`, applied to TEST only). `owner_id` is a plain string (`demo`). The first portfolio of an owner is its default (`POST /api/portfolios/{id}/default` changes it; deleting the default promotes the oldest remaining one). A holding is `{security_id, quantity > 0, avg_cost >= 0, currency INR|USD}`: the security must be active in `news.securities` and the currency must be the one it trades in (USD for US listings). All row errors are returned at once (422), at most 50 holdings; the same checks run in code (`core/holdings.py`) and as database CHECK constraints. A zero average cost is allowed and reads as a 0.0 unrealized return (it used to divide by zero).
21. **Endpoints.** `POST /api/portfolios` and `/api/portfolios/import` (the same JSON import), `POST /api/portfolios/import-sample` (the four repo samples: bare tickers become `NSE:` ids, the currency follows the listing), `GET/PUT/DELETE /api/portfolios/{id}`, `GET /api/securities/search`, `POST /analyze/{owner_id}[?sync=true]`, `POST /api/runs`, `GET /api/runs/{id}`, `GET /api/runs`. The older `POST /analyze` (sample or holdings in the body) and `GET /runs/{id}` are unchanged and synchronous; `?sync=true` is the synchronous form of the new owner and run endpoints.
22. **Async runs.** 202 `{run_id}` at once, executed on a bounded worker pool; at most 1 run per owner and 2 in the process (settings), else 429 with `Retry-After` and the scope. A failed run is stored as `failed` with its error and frees its slot. Each run has its own LLM client, so the free-tier spacing is per run: two concurrent runs can double the call rate.
23. **Progress.** A hook in the node wrapper reports start and end of every one of the 12 stages (`stage`, `stage_index`, a line of real counts such as "3 flagged (2 risk, 1 opportunity), 0 over the cap", seconds, LLM calls, timestamps). It only observes: a test shows the final state is identical with and without it, and that a broken observer cannot break a run. Stages that never run (the conflict resolver when nobody conflicts) end as `skipped`.
24. **Where run state lives.** The in-memory registry answers every status request and is always current; `app.analysis_runs` is written by ONE background thread, newest state per run winning. This is deliberate: a write to the Neon database from this machine takes about 1.3 s, which inline would have added over 15 s to every run. A database failure is counted, never fatal. After a restart a run is read back from the database.
25. **LangSmith.** Off unless `LANGSMITH_TRACING=true` AND `LANGSMITH_API_KEY` are set. Even when off, the run executes inside `tracing_context(enabled=False)`, so a stray `LANGSMITH_TRACING` / `LANGCHAIN_TRACING_V2` in the shell cannot send an unredacted trace. When on, the client is built with `hide_inputs`, `hide_outputs` and `hide_metadata` = `tracing.redact`, which blanks quantity, cost, price, value, unrealized / P&L, owner / user id and e-mail keys (weights and signals are kept) and scrubs e-mail addresses from strings. Tests cover the redaction, the off-by-default behaviour and that the client is constructed with the hooks; no trace is sent in any test.
26. **Run accounting** (in the run metadata and `meta.accounting`): LLM calls, repairs and tokens by node (the client attributes each call to the node's thread), retries, cache hits and misses for sector narratives and fundamentals, per-node seconds, duration. **`AGENTS_LLM_MAX_CALLS_PER_RUN` is now 60** (was 8): worst realistic case = 8 sectors x 2 + 8 stocks x (fundamental 2 + recheck 2) + 3 resolutions x 2 + synthesis and one regeneration = 57; a typical run is about 25. At 10 requests a minute that is 2.5 minutes of LLM time at least.
27. **App database target.** `APP_DB_TARGET` (default `main`) says where portfolios and runs live. If its tables are not migrated, portfolio endpoints answer 503 with the migration command and runs are kept in memory only (`/health` shows `app_db`). To use the API now, set `APP_DB_TARGET=test`.
